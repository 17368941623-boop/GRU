# 0908 训练包代码审查记录（2026-09-09）

## 结论

当前版本没有发现阻止服务器正式训练的问题。原本地任务已按要求终止，正式 `outputs/` 目录尚未
产生结果；本次验证输出全部隔离在 `reports/optimized_causal_smoke/` 和
`reports/server_package_smoke/`，不能当作论文正式结果。

## 已修正问题

1. 原因果脚本在每个 bootstrap 中重新对全部 20×20×30 个变量—滞后组合执行 PC1+MCI，导致
   本地第一轮 bootstrap 长时间无法结束。现改为：父运行隔离的相关性筛选 → 候选图上的一次
   PC1/MCI → 固定条件父集、仅对预选边做分段 bootstrap。
2. 原 5 进程脚本在多 GPU 服务器上会把全部训练发送到同一个 `cuda` 设备。现自动按
   `cuda:0`、`cuda:1`……分配；单 GPU 默认仅启动一个训练进程。
3. `--device` 原先不能接收 `cuda:0`/`cuda:1`。现支持显式 GPU 编号并检查编号是否存在。
4. 被中断的单次实验若留下部分文件，原断点续跑可能被已有文件阻止。现 shard 调度器会跳过
   checkpoint+metrics 均完整的实验，并自动重建不完整实验。
5. 验证阶段记录的 weighted Huber loss 原来是批均值的近似加权。现按所有元素的实际权重和汇总。
6. 阀门活跃片段的裁剪原来在差分模式下实际使用了二阶差分。现直接按阀门一阶变化量选取。
7. ADF 审计对分段常值阀门产生的大量奇异矩阵告警已局部屏蔽；该审计不参与边筛选。
8. 数据筛选得到的纯 PCMCI 图不再误收只因物理先验进入候选集的边；DK&CD 图仍保留通过相同
   MCI、FDR 和稳定性门槛的物理候选边。

## 验证结果

- 所有 Python 文件通过字节码编译。
- Linux 启动、停止和多进程脚本通过 Git Bash 的 `bash -n` 语法检查。
- 预检通过：40 个历史特征、20 个图节点、8 个未来可控阀门；H=15 和 H=30 的首个输出对
  后续未来控制的最大梯度均为 0；KAN 导通函数最小增量为正。
- 缩小版因果发现成功完成相关性筛选、PCMCI、固定父集 bootstrap，并生成全部 6 种图文件。
- 8 个实验变体均成功前向计算，输出形状统一为 `[batch, horizon]`。
- 主模型 `dkcdv_select_lag_kan` 已在本机 CUDA 上用 128 个训练窗口、64 个验证窗口完成一轮
  真实反向传播，并成功保存 checkpoint、逐步预测和指标。
- 缩小版汇总正确识别为 1/80、不完整，因此不会生成可用于正式测试的冻结清单。

## 服务器运行边界

- 一键流程默认训练 H=15（150 s）；设置 `PREDICT_STEPS=30` 才是 5 min。
- 默认 bootstrap=20；论文最终图如算力允许可改为 50，并设置 `FORCE_CAUSAL=1` 重建图。
- 一键流程只运行开发训练和验证汇总，绝不自动读取冻结测试集。
- 服务器必须先在 conda `pytorch` 环境中安装与 CUDA 匹配的 PyTorch；脚本只安装其余依赖，
  不会用 pip 覆盖服务器的 PyTorch。
